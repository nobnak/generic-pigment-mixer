# ピグメントミキサー調査・検証記録 (Technical Report)

## 1. 調査背景と目的

3Dプリンター用フィラメント混色プロジェクト [filament-mixer](https://github.com/justinh-rahb/filament-mixer) で開発された 2 つの機械学習ピグメントミキサー関数（**PolyMixer** / **GPMixer**）および物理ベースの **Kubelka-Munk (KM) 法** について、以下の技術的検証を実施した。

1. **シェーダーへの移植可能性**: GPU（HLSL / Compute Shader）上でリアルタイム実行可能か。
2. **手法の比較とシェーダー適性**: どの手法がリアルタイムレンダリングに最適か。
3. **加色・減色・KM法リファレンスとの比較**: 視覚的・数値的な混色特性の差異。

---

## 2. 2つのミキサー関数の比較とシェーダー適性

| 項目 | PolyMixer (多項式回帰) | GPMixer (ガウス過程回帰) |
| :--- | :--- | :--- |
| **数理モデル** | 4次多項式回帰 (7変数: $R_1,G_1,B_1,R_2,G_2,B_2,t$) | RBFカーネル + ガウス過程回帰 |
| **パラメータ規模** | 330項の単項式基底 ＋ $330 \times 3$ 係数 (約 4KB) | 2,000点の7Dサポート点 ＋ 3D双対係数 (約 80KB) |
| **GPU演算特性** | **純粋ALU (約330積和演算、FMA)** | **2,000反復ループ (7D距離2乗 ＋ exp ＋ 積和)** |
| **テクスチャ/バッファ依存** | **完全不要** (定数展開可能) | 必須 (`StructuredBuffer` または 2D Texture) |
| **精度 ($\Delta E$ vs Mixbox)** | **2.07** (青＋黄＝鮮やかな緑) | **1.79** (高精度) |
| **シェーダー適性** | **◎ 最適 (本採用)** | **✕ 不適 (メモリ帯域・ALU過大)** |

### 判定
- **PolyMixer をシェーダー移植として本採用**: 外部メモリやテクスチャを一切消費せず、ピクセルシェーダーの ALU のみで完結し、分岐やワープダイバージェンスも発生しないため、GPUアーキテクチャに極めて親和性が高い。
- **GPMixer は不適**: 1ピクセルあたり2,000回のテクスチャ読み出しと指数関数ループが発生するため、フィルレートに深刻な影響を与える。

## 3. KM法（Kubelka-Munk）リファレンス検証の経緯

### 課題の発生：素のKM物理モデルが暗く濁る問題
KM法の物理反射シミュレーション（38波長積分＋Saunderson表面反射補正）を C# で実装したところ、指定した RGB（例: Blue `(0, 33, 133)` や Yellow `(252, 211, 0)`）と大きく乖離し、端点（$t=0, 1$）すら暗く濁る現象が確認された。

#### 物理計算が出力した実測RGB
- **Yellow 100% 顔料**: `RGB(222.4, 159.3, 0.0)`（純黄ではなく暗い黄土色）
- **Blue 顔料 (0.7C+0.3M)**: `RGB(53.7, 81.9, 169.5)`（赤54, 緑82が混入し彩度が低下）
- **White 100% 顔料**: `RGB(161.0, 148.8, 127.5)`（純白ではなく薄暗いベージュ）

#### 根本原因
1. **Saunderson表面反射**: 媒質表面でのFresnel反射（約4%）により、物理顔料には無条件で白色環境光が混ざるため、モニターの最高彩度・高輝度な原色（純青・純黄・純白）は**物理顔料の色域外（Out-of-Gamut）**となる。
2. **Mixboxの残差ベクトル（Residual）の欠落**: Mixbox（および `filament-mixer` の Python API）は、$\text{Residual} = \text{RGB} - \text{KM}(c)$ を保持し、$\text{Output} = \text{KM}(c) + \text{Residual}$ として加算することで端点色を100%完全復元していた。素のKM法にはこれが欠けていた。

### 方針1の検証（残差補正 Residual の追加）
端点 $t=0, 1$ で指定RGBと完全一致するように、線形補間された残差を加算する補正を導入。
- **結果**: 端点の色は100%一致したが、**中間色（$t=0.5$）は暗いオリーブ色（Muddy Olive）に留まり、鮮やかなグリーンにはならなかった**。
- **原因**: `filament-mixer` の顔料データは大雑把なガウス曲線（正規分布）による擬似スペクトルのため、物理混色スペクトル自体が緑の波長を十分に反射できない構造的限界（公式 docs/EXPERIMENTS.md でも Mean $\Delta E$ 11.77 の限界として明記）。

### 方針2への移行（最終結論）
不完全なオリーブ色を出す KM 物理行を排除し、**「加色（RGB Lerp） vs 減色（CMYK Lerp） vs ピグメント混合（PolyMixer HLSL）」の 3 者比較** に整理。
- 加色（灰色に濁る）や減色（黒沈みする）に対し、PolyMixer（HLSL）がいかに鮮やかな緑と自然な混色カーブを生み出しているかが一目でわかる明快なビジュアル資料を確立した。

## 5. Spectral.js の調査と Mixbox 系との比較検証

### 5.1 基本アーキテクチャ
[Spectral.js](https://github.com/rvanwijnen/spectral.js)（Ronald van Wijnen 氏作、MITライセンス）は、重い非線形逆問題最適化（SLSQP 等）を排除し、独自の高速解析パイプラインを採用した物理顔料混色ライブラリである。

1. **7原色ルールベース分解**:
   任意の線形 RGB を `min`/`max` による分岐なしの算術式で White, Cyan, Magenta, Yellow, Red, Green, Blue の 7 原色成分比率へ瞬時に分解。
2. **38波長スペクトル反射率 $R(\lambda)$ の生成**:
   可視光域（380〜750 nm、10 nm刻みの 38 バケット）について、7原色の基底反射率ベクトルとの内積から各色の反射スペクトル $R_i[0..37]$ を生成。
3. **単一定数 Kubelka-Munk 混合**:
   散乱係数 $S$ を波長によらず一定と仮定し、吸収散乱比 $F(R) = (1 - R)^2 / (2R) = K/S$ を導出。
   混合比率 $f$、着色力 $T$（Tinting Strength）、輝度 $L$ から実効濃度 $C = f^2 \cdot T^2 \cdot L$ を算出し、濃度加重平均 $(K/S)_{mix} = \sum C_i (K/S)_i / \sum C_i$ を計算。
4. **反射率逆算と等色関数積分**:
   $R_{mix} = 1 + (K/S)_{mix} - \sqrt{(K/S)_{mix}^2 + 2(K/S)_{mix}}$ により反射率を逆算し、CIE 1931 等色関数（CMF）と D65 光源スペクトルとの内積積分で CIE XYZ へ変換後、sRGB へ復元。

### 5.2 比較一覧（PolyMixer vs Spectral.js vs Mixbox）

| 比較項目 | **PolyMixer** (filament-mixer) | **Spectral.js** (`spectral.glsl`) | **Mixbox** (本家) |
| :--- | :--- | :--- | :--- |
| **基本原理** | 4次多項式回帰 (330項) | 単一定数 Kubelka-Munk (38波長) | 実測絵具スペクトル＋7次元潜在空間 |
| **RGB $\to$ 内部変換** | なし (直接多項式評価) | ルールベース (min/max 7成分分解) | 3D LUT (テクスチャ参照) |
| **混合空間** | 多項式空間 | スペクトル $K/S$ 濃度空間 | 潜在空間 (線形補間) |

### 5.3 補色ペア（赤＋シアン、緑＋マゼンタ）で Spectral がくすむ原因の分析

4 方式直接比較画像において、PAIR 3（赤＋シアン）および PAIR 4（緑＋マゼンタ）の中間色において、PolyMixer が温かい暗褐色（アーストーン）に着地するのに対し、Spectral.js は**冷たくくすんだ灰色・スレート調の紫色**を通過する現象が確認された。

#### ① 物理的必然性（共通反射窓の不在）
- 青＋黄が鮮やかな緑になるのは、500〜550 nm に両者が共に光を反射する「共通窓」があるため。
- 一方、赤（長波長反射）とシアン（短〜中波長反射）は波長が完全に排他的であり、共通反射窓が存在しない。
- Kubelka-Munk の吸収散乱比 $K/S$ が可視光全域で急増するため、物理的に全光が吸収され、**彩度がゼロ（無彩色グレー）に向かって沈み込む**。

#### ② 合成 7 原色スペクトルの急峻な相殺 vs 実在絵具のアーストーン
- **Mixbox / PolyMixer**: 実在するカドミウムレッドやフタロシアニングリーンの実測スペクトルに基づき、顔料の不純物や長波長側での散乱が残るため、絵画で親しまれる「バーントアンバー（焦茶色）」のような温かい濁色になる。
- **Spectral.js**: sRGB キューブを埋めるための人工的な理想原色であるため、中〜長波長が綺麗に相殺された結果、短波長（紫・青端）の微弱な基底残差だけが浮き上がり、**冷暗なスレートグレー**として知覚される。

#### ③ 輝度非対称性による彩度最低点の偏位
- 赤（$L \approx 0.21$）とシアン（$L \approx 0.72$）には約 3.4 倍の輝度差がある。
- 実効濃度 $C = f^2 \cdot T^2 \cdot L$ により、波長相殺が最大となるポイントが中央（$t=0.5$）ではなく **シアン寄りの $t=0.75$ へ偏位**する。
- 数値測定結果において、$t=0.75$ で RGB: `[0.544, 0.498, 0.582]`（色相 $272.6^\circ$、**彩度 14.6%**）という平坦な無彩色領域が露出することが確認された。

### 5.4 実務における選定指針
1. **リアルタイム 3D / ポストプロセス / ゲーム用途**:
   - **PolyMixer を強く推奨**。テクスチャ不要・0ループ・330 FMA の高速性により、パイプラインのボトルネックにならない。
2. **デジタルペイント / パレット調合シミュレータ**:
   - **Spectral.js が有利**。複数顔料の任意比率ブレンドや着色力（隠蔽力）の調整が数学的に自然に行える。
