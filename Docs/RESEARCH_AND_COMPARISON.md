# ピグメントミキサー調査・検証記録 (Technical Report)

## 1. 調査背景と目的

3Dプリンター用フィラメント混色プロジェクト [filament-mixer](https://github.com/justinh-rahb/filament-mixer) で開発された 2 つの機械学習ピグメントミキサー関数（**PolyMixer** / **GPMixer**）および物理ベースの **Kubelka-Munk (KM) 法** について、以下の技術的検証を実施した。

1. **シェーダーへの移植可能性**: GPU（HLSL / Compute Shader）上でリアルタイム実行可能か。
2. **手法の比較とシェーダー適性**: どの手法がリアルタイムレンダリングに最適か。
3. **加色・減色・KM法リファレンスとの比較**: 視覚的・数値的な混色特性の差異。

---

## 2. 2つのミキサー関数の比較とシェーダー適性

| 項目 | PolyMixer (多項式回帰) | GPMixer (ガウス過程回帰) |
| :--- | :--- | :--- |
| **数理モデル** | 4次多項式回帰 (7変数: $R_1,G_1,B_1,R_2,G_2,B_2,t$) | RBFカーネル + ガウス過程回帰 |
| **パラメータ規模** | 330項の単項式基底 ＋ $330 \times 3$ 係数 (約 4KB) | 2,000点の7Dサポート点 ＋ 3D双対係数 (約 80KB) |
| **GPU演算特性** | **純粋ALU (約330積和演算、FMA)** | **2,000反復ループ (7D距離2乗 ＋ exp ＋ 積和)** |
| **テクスチャ/バッファ依存** | **完全不要** (定数展開可能) | 必須 (`StructuredBuffer` または 2D Texture) |
| **精度 ($\Delta E$ vs Mixbox)** | **2.07** (青＋黄＝鮮やかな緑) | **1.79** (高精度) |
| **シェーダー適性** | **◎ 最適 (本採用)** | **✕ 不適 (メモリ帯域・ALU過大)** |

### 判定
- **PolyMixer をシェーダー移植として本採用**: 外部メモリやテクスチャを一切消費せず、ピクセルシェーダーの ALU のみで完結し、分岐やワープダイバージェンスも発生しないため、GPUアーキテクチャに極めて親和性が高い。
- **GPMixer は不適**: 1ピクセルあたり2,000回のテクスチャ読み出しと指数関数ループが発生するため、フィルレートに深刻な影響を与える。

## 3. KM法（Kubelka-Munk）リファレンス検証の経緯

### 課題の発生：素のKM物理モデルが暗く濁る問題
KM法の物理反射シミュレーション（38波長積分＋Saunderson表面反射補正）を C# で実装したところ、指定した RGB（例: Blue `(0, 33, 133)` や Yellow `(252, 211, 0)`）と大きく乖離し、端点（$t=0, 1$）すら暗く濁る現象が確認された。

#### 物理計算が出力した実測RGB
- **Yellow 100% 顔料**: `RGB(222.4, 159.3, 0.0)`（純黄ではなく暗い黄土色）
- **Blue 顔料 (0.7C+0.3M)**: `RGB(53.7, 81.9, 169.5)`（赤54, 緑82が混入し彩度が低下）
- **White 100% 顔料**: `RGB(161.0, 148.8, 127.5)`（純白ではなく薄暗いベージュ）

#### 根本原因
1. **Saunderson表面反射**: 媒質表面でのFresnel反射（約4%）により、物理顔料には無条件で白色環境光が混ざるため、モニターの最高彩度・高輝度な原色（純青・純黄・純白）は**物理顔料の色域外（Out-of-Gamut）**となる。
2. **Mixboxの残差ベクトル（Residual）の欠落**: Mixbox（および `filament-mixer` の Python API）は、$\text{Residual} = \text{RGB} - \text{KM}(c)$ を保持し、$\text{Output} = \text{KM}(c) + \text{Residual}$ として加算することで端点色を100%完全復元していた。素のKM法にはこれが欠けていた。

### 方針1の検証（残差補正 Residual の追加）
端点 $t=0, 1$ で指定RGBと完全一致するように、線形補間された残差を加算する補正を導入。
- **結果**: 端点の色は100%一致したが、**中間色（$t=0.5$）は暗いオリーブ色（Muddy Olive）に留まり、鮮やかなグリーンにはならなかった**。
- **原因**: `filament-mixer` の顔料データは大雑把なガウス曲線（正規分布）による擬似スペクトルのため、物理混色スペクトル自体が緑の波長を十分に反射できない構造的限界（公式 docs/EXPERIMENTS.md でも Mean $\Delta E$ 11.77 の限界として明記）。

### 方針2への移行（最終結論）
不完全なオリーブ色を出す KM 物理行を排除し、**「加色（RGB Lerp） vs 減色（CMYK Lerp） vs ピグメント混合（PolyMixer HLSL）」の 3 者比較** に整理。
- 加色（灰色に濁る）や減色（黒沈みする）に対し、PolyMixer（HLSL）がいかに鮮やかな緑と自然な混色カーブを生み出しているかが一目でわかる明快なビジュアル資料を確立した。
